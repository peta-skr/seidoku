## 1. 作るもの

1本の記事を使う日の流れ（企画メモ 4章）に沿って書く。

### 記事を登録する

- 記事の URL を入れると、本文とタイトルが保存される
  - 既に登録済みの場合は、登録済みですと表示する。

### 問いを作る

- 保存した記事から問いと模範解答の要点が作られ、本文に根拠がある問いだけが残る
  - 1記事に対して1回作成する。

### 読む前と読みながら

- 記事を読む前に、問いだけを見られる（要点は見えない）
- 読みながら、問いの答えを書き込める
  - 読みながら答えるのは、問いを持って、理解できているかを確かめながら読むため。本文を閉じて思い出す練習は、翌日以降の復習でする
  - 本文から答えが見つからない問いは、自分で「もう無理」と思ったら要点を見て確かめられる。その日のうちに解き直しはせず、ほかの問いと同じく翌日に出る
  - 時間制限を付けて、時間になったら要点を見るようにするのは将来の案。今は入れない
- 1日に読める記事は、既定で1本にする
  - 1本は上限で、毎日読む目安ではない。復習の上限が1日5問のとき、復習が回る目安は週2〜3本（[ADR 0001](adr/0001-scheduling.md) の試算）
  - 問いを全部埋めた時点で1本と数える。要点を見て終えた問いも、埋めたものとする
  - 上限を超えた記事も読めて、問いも埋められる。書いた答えは残るが、復習には入らない

### 翌日以降の復習

- 「今日の復習」を開くと、その日に出題する問いが出る
- 最初の復習は、問いを埋めた日の翌日に出る
- 問いに答えて自己評価すると、次の出題日が決まる
  - 1日の復習数に上限を入れる（既定は5問）。フェーズ1では値をコードに直接書き、画面からは変えない。卒業は入れない。
    - 卒業を入れない理由としては、長期記憶に定着させるには忘れたころに何度も思い出す必要があるから。
    - 出題の間隔を十分に長く伸ばせば、卒業がなくても復習が溜まり続けることはないと考えている。ただし、読む本数が復習の上限に見合っていることが前提になる。
    - 企画メモ 6.3 の卒業の方針も、これに合わせて直した。方式と設定は [ADR 0001](adr/0001-scheduling.md) に書いた。

### 全体

- PC のブラウザで、画面から操作する
- 自分の PC の中（ローカル）で動かす

### アプリで記録するもの（使いながら振り返る材料）

- 問いの難しさ：入力欄は作らず、4段階の自己評価と言えた要点の割合から読み取る

### 自分でメモするもの

- 全体的な使いやすさ（詰まったところ、ハードルが程よくなくてつまらなかったところなど）
- 読むのにかかった時間：問いを開いてから問いを全部埋めるまでの時間を、時計で測って手元の Markdown に書く。検証のための記録で、アプリの機能ではないため、アプリには持たせない

## 2. 作らないもの

フェーズ1で確かめたいのは、コアである問いの作成と反復学習だけ。それ以外は、コアを確かめるのに必要がなければ作らない。

- 記事が更新されたときの問いの再生成：自分で登録した記事が使い始めてすぐに更新されることは少ないため。MVP 以降で考える
- デプロイ：フェーズ2に回す。デプロイすると、他人が記事を登録して LLM の費用が増えないようにする仕組みや、SSRF の対策、インフラの構築が必要になる。フェーズ1で見せる形は、README のスクリーンショットや GIF にする
- 認証：ローカルで自分だけが使うため不要。フェーズ2で GitHub OAuth を入れる
- スマホ対応：PC のブラウザで使う想定にしたため
- 画面の見た目：操作できれば十分なので、最小限にとどめる
- 問いの回答の自動採点：自己評価で足りるため。企画メモでは MVP の後（記述した回答の LLM による採点）
- 記事の自動収集（RSS など）：記事は自分で URL を入れれば足りるため。フェーズ2で作る
- 記事のレコメンド：コアの外にあり、選別は使いながら試して詰めると決めたため。フェーズ2以降（Issue #2）
- 1記事あたりの問いの数の設定：問いの数は、記事の中身に合わせて生成するときに決まるため。必要になったら考える

## 3. 進め方

「1. 作るもの」が一通り動いたら使い始め、使いながら欲しい機能を少しずつ足していく。使って気づいたことはメモと GitHub の Issue に残し、次に足す機能を選ぶ材料にする。

## 4. 完成と言える状態

記事の URL を入れてから、問いを埋め、翌日以降に「今日の復習」で自己評価して次の出題日が決まるまでを、画面の操作だけで毎日通せる。

## 5. 2週間使ったあとに見ること

使い始めて2週間たったら、次の項目を見て、このまま機能を足すか、先に直すかを決める。数字は最初の目安で、使い始める前に見直す。

| 見ること | 目安 | 外れたときに疑うところ | どこから分かるか |
|---|---|---|---|
| 復習をした日数 | 14日のうち10日以上 | 1日の量が多すぎる（読む本数、復習の上限） | 復習の記録 |
| 繰り越した復習の数 | 14日目に5問以下（1日分以内） | 読む本数が多すぎる | 復習の記録 |
| 1日にかかった時間 | 記事を読む日で60分以内、復習だけの日で20分以内 | 記事の長さ、1記事あたりの問いの数 | 手元のメモ |
| 言えた要点の割合 | 2回目以降の復習で、半分以上の要点を言えた問いが7割以上 | 記事が自分のレベルに合っていない（Issue #2）、問いが細かすぎる | 復習の記録 |
| 的外れな問い、本文から答えが見つからない問いの数 | 1記事あたり1問以下 | 問いを作るプロンプト、根拠の検証 | 手元のメモ |

- 目安を外れた項目が2つ以下なら、そのまま使い続けて機能を足す
- 3つ以上外れたら、機能を足す前に、いちばん外れた項目の原因を1つ選んで直す
- 復習をした日数が14日のうち5日に届かなかったら、道具の形そのもの（問いの数、1問にかける時間、読む流れ）を見直す
